# Codex / ChatGPT plan

Mainframe's Brain provider can use the installed official `codex app-server`
through stdio. Sign in with the official Codex client or `codex login`, select
**Codex / ChatGPT plan**, and press **Connect / Retry**. No OpenAI API key is
required. A successful model reply, rather than account discovery alone, makes
the connection ready. Local Ollama and optional API-key providers remain
available, with their existing saved model choices preserved.

Capri starts and owns one child process while this provider is selected. It does
not copy tokens, change Codex's global configuration, or sign other clients out.
Disconnect and close affect only Capri's work and child. Provider/model changes
and Stop revoke pending native work and speech; Stop waits for the actual turn's
interruption before another turn can begin. Hide, Quiet, sleep and session lock
also revoke ordinary chat, pending tool proposals, queued connections and speech.
Repeated sleeping or locked ticks do not repeatedly cancel the provider. A failed or uncertain turn is never
automatically replayed. Retry starts a fresh connection and resumes only a
matching account/model's dedicated Capri thread.

Ordinary chat, image requests, memory folding and native job decisions use the
same provider boundary and their existing Brain instructions. Chat, typed action
planning, vision, memory folding and other structured steps have separate thread
lanes. Existing local speech handles accepted microphone transcripts and spoken
replies; Codex does not replace ASR or TTS. The new bubble streaming displays
actual assistant text and suppresses cancelled generations.

Only explicitly negotiated `capri_plan_*` dynamic tools are exposed for action
routing. They return typed **proposals**, not execution receipts. After a
successful completed turn, the existing Hands/Security path validates and runs
those proposals. Cancellation, failure and unexpected server requests cannot
grant effects. Native jobs retain their target, frame, session and permission
checks. The child disables shell, file/environment access, browser, app/plugin,
web, unrelated MCP and agent tools; these are not alternate action routes.

The companion uses a neutral private conversation directory and rejects project
instruction sources. Codex 0.163.0 still loads its user-global AGENTS.md even when
project-document loading and environment access are disabled. Capri preserves
that file, records the source, and supplies explicit app-owned instructions that
exclude coding-project, repository and workflow requirements from companion
conversation. It does not alter HOME or CODEX_HOME.

The app-server protocol is version dependent. This adapter was tested against
Codex CLI **0.163.0** and schemas generated by that installed CLI with
`codex app-server generate-json-schema --experimental`. Dynamic tools require
experimental API negotiation; an incompatible server fails visibly instead of
falling back to unrestricted tools. See the [official app-server
protocol](https://learn.chatgpt.com/docs/app-server).

Run deterministic protocol checks:

```sh
dotnet run --project tests/brain/BrainChecks.csproj -c Release
```

The optional `--lifecycle /absolute/private/test-directory` check runs real Pet
transitions with delayed provider IO. It requires an explicitly unused private
Xvfb display from `:192` through `:219`, `CAPRI_BRAIN_TEST_XVFB=1`, private
XDG configuration/data directories, and unset Wayland/Hyprland session variables.
Check both the X socket and lock before allocating the display. It uses the
shipped BareDesk fallback for window discovery; physical lock and desktop input
remain separate host checks. Never run it against the owner's desktop.

The explicitly opted-in live check uses the current managed sign-in, creates
only dedicated test threads and tests streaming, follow-up, interruption,
synthetic-image input, typed proposals and process restart/resume. Its directory
contains private account fingerprints and thread identifiers; do not publish it.

```sh
dotnet run --project tests/brain/BrainChecks.csproj -c Release -- --live /absolute/private/test-directory
```

A test thread or model catalog is not entitlement proof for every model. A model
must complete inference, and image use must complete an image request. Model or
authentication errors remain visible in Mainframe. Physical microphone input,
audibility and native visual smoothness require separate host checks.
