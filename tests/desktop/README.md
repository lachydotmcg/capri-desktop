# Native desktop adapter checks

Run `dotnet run --project tests/desktop/Capri.Desktop.Tests.csproj` from the repository root. The fixtures use synthetic windows and private Unix sockets. They do not start Capri, capture screens, inject host input, close applications, or require a display server.

An optional, separate `--read-only-host` argument queries the current Hyprland session and reports only counts, lock state, pointer validity and compositor version. It does not dispatch actions. Do not treat that probe as evidence of successful window control or rendered motion.

The adapter retains Avalonia's XWayland surface and maps compositor logical coordinates to each matching Avalonia/XRandR output. Monitor scale and orientation determine logical extent; the already-oriented client and cursor coordinates are not rotated again. Outputs with unmatched or ambiguous identities remain unavailable rather than inheriting the primary monitor's scale. The original X11 backend remains selected on an actual X11 session.

The native command socket uses a two-second request bound and a 4 MiB response limit. The event socket invalidates geometry on workspace, window, fullscreen and monitor changes. Hyprland does not emit continuous client move/resize events, so a 250 ms socket refresh supplements events. Pointer refresh is demand-driven. Requests operate on exact compositor addresses; selected windows also bind process UID/start ticks, geometry, layout and a 15-second selection lifetime. A close is sent once and succeeds only after the window disappears. Minimize moves an ungrouped window to `special:minimized`; focusing a window minimized by this connection restores its original workspace. Pre-existing minimized windows require restoration by the compositor.

Complete snapshot reads and publication are serialized, with a final lock/session check, so an older unlocked capture cannot replace a newer locked one. Restoring a minimized window requires a fresh identity, session, layout and restored-workspace check before the separate focus request. A failed or uncertain restore is never retried automatically. Visible floating and pinned windows retain their clipped segments across outputs with distinct active workspaces; tiled/fullscreen windows stay on their owning output.

The 0.56 Lua dispatcher and Hyprlang dispatcher forms are selected using a read-only dialect probe, never by retrying a failed mutation. Protocol references: [Hyprland IPC](https://wiki.hypr.land/ipc/), [v0.56.2 command handling](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/debug/HyprCtl.cpp), [v0.56.2 Lua dispatchers](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/config/lua/bindings/LuaBindingsDispatchers.cpp), and [XWayland coordinate mapping](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/managers/XWaylandManager.cpp).

Physical qualification remains separate: fractional-DPI dragging, native window focus/minimize/close, overlapping floating windows, output disconnect/reconnect, and the pet's motion and bubble/pill placement need real disposable-session and rendered checks. IPC focus history plus floating/fullscreen state is an approximation of stacking order, not a compositor-provided exact stacking feed. The desktop service does not implement force-kill or tab keyboard input; generic computer jobs must supply their own target-bound input/verification path. The sprite definitions, resource bytes, drawing code, and non-Hyprland surface geometry remain unchanged.

For Xvfb smoke runs, remove `WAYLAND_DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` from the test environment so the synthetic X display cannot be confused with the owner's active compositor session.
